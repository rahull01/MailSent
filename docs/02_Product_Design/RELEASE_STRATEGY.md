## The Governing Principle

Release is phased by **capability and by validation**, not by calendar. Each phase is a set of capabilities that together deliver a complete, tested, meaningful step a customer can live with. The exact order of execution lives in the Master Workflow; this document defines the principle that governs.

Each phase is gated by the Golden Rule and the Feature Formula: no phase opens until the capability is validated against a real customer problem, tested for accuracy, and approved. Phases are not tied to dates; a phase ships only when it truthfully works, not when a calendar says so.

## The Phases

- **Phase A — Foundation: from health to truth.** The capabilities to add a domain, measure health, and diagnose a root cause for a single domain. This phase is complete when a customer can honestly see their health and a real cause.

- **Phase B — From diagnosis to business.** The capabilities to explain, score, and prioritize, so a customer understands and knows what to do first. This phase is complete when a non-technical customer can read a finding and know the next action.

- **Phase C — From action to assurance.** Guidance, fix verification, monitoring, and alerting. A user can not only fix, but verify the fix held and stay ahead through early warning.

- **Phase D — From memory to evidence.** Reporting and readiness, so a user can prove health to a client, auditor, or board.

- **Phase E — From single to portfolio.** Multi-organization, portfolio, and management of many clients, so a user can manage a portfolio at once.

- **Phase F — From feedback to improvement.** Feedback, adoption, and refinement driven by what real customers said.
