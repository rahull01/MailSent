# MailSent — Constitution

## Core Principles

### I. The Golden Rule (Supreme Governing Rule)
"No feature is approved because it is technically impressive. Every feature must solve a validated customer problem and create recurring value. (Will a customer pay a monthly subscription for this for 12+ months? If NO -> REJECT)."

### II. Sell Confidence, Never Fabricate Truth
MailSent is an AI Email Infrastructure Intelligence Platform selling confidence. We never guess delivery states (INV-01, INV-05), never lie in errors, and report only verifiable facts.

### III. The Natural Flow (Product DNA)
The product follows an ordered, non-negotiable flow:
Scanner -> Analyzer -> Alignment Intelligence -> AI Explanation -> Business Impact -> AI Action Queue -> Guided Fix -> Continuous Monitoring -> Alerts -> Reports -> Agency Dashboard.

### IV. Non-Negotiable Engineering Rules (N1 - N8)
- N1: No unvalidated feature.
- N2: No fabricated or guessed delivery state.
- N3: No silent data loss.
- N4: No secrets in code or repos.
- N5: No untested production path.
- N6: No lying to the user.
- N7: No bypassing the approval framework.
- N8: No security review shortcuts.

### V. Direction of Truth
Implementation follows documentation; documentation never follows implementation. Code follows architecture; architecture is frozen.

### VI. Locked Architecture & Tech Stack
Java 21, Spring Boot, Maven, Next.js, TypeScript, Tailwind CSS, PostgreSQL, Redis, Docker Compose. 15 decoupled Bounded Contexts. Multi-tenant isolation by organization_id (INV-09) and deterministic lineage (INV-11).

## Quality Gates & Definition of Done

A task is Done only when all 10 criteria pass:
1. Validated (Golden Rule)
2. Works per contract
3. Tested (T-MAT full coverage)
4. Verified with evidence
5. Reviewed (Constitution §26)
6. Documented
7. Observable (O-MAT)
8. Secured (S-MAT, least privilege)
9. Honest (Attributable AI, truthful UI)
10. Committed & Clean
